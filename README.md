## 1. 제작 목적

계획을 세울 때 예상한 시간과 실제로 작업한 시간이 얼마나 다른지 확인하고 싶었습니다.

예를 들어 GNS3 실습은 설정 자체보다 오류를 찾고 해결하는 데 더 오래 걸릴 수 있습니다. 이런 차이를 기록하지 않으면 다음 계획에서도 시간을 비슷하게 잘못 예상할 수 있습니다.

이 앱에서는 다음 흐름으로 활동을 관리합니다.

1. 기간과 성공 기준을 정하고 계획을 세웁니다.
2. 계획에 필요한 할 일을 등록합니다.
3. 실제로 작업한 시작·종료 시각과 내용을 기록합니다.
4. 예상 시간과 실제 시간의 차이를 확인합니다.
5. 돌아보기에서 정한 개선점을 다음 계획으로 넘깁니다.

ALEPH 과제 6의 요구사항을 바탕으로 제작했으며, 예시 데이터 대신 직접 정한 준비 활동과 실제 활동 기록을 입력했습니다.

## 3. 주요 기능

### Plan — 계획과 할 일

계획에는 다음 정보를 저장합니다.

- 고유 ID
- 계획 제목
- 시작일과 종료일
- 우선순위
- 성공 기준
- 예상 시간
- 이전 돌아보기에서 가져온 개선점

계획을 수정하면 **수정 직전의 내용이 별도 이력으로 보존**됩니다. 계획 ID는 유지되며, 현재 내용과 이전 내용을 나누어 확인할 수 있습니다.

할 일에서는 다음 기능을 사용할 수 있습니다.

- 할 일 추가와 수정
- 완료 처리
- 완료한 할 일을 진행 중으로 되돌리기
- 할 일 삭제
- 제목과 태그 검색
- 전체·진행 중·완료·지연·막힘 필터
- 마감일·우선순위·예상 시간 기준 정렬

각 할 일에는 마감일, 우선순위, 태그, 예상 시간을 저장합니다. 정렬 값이 같은 경우에는 ID 오름차순으로 순서를 정합니다.

### Do — 실제 실행 기록

할 일별로 실제 활동을 따로 기록합니다.

| 항목 | 설명 |
|---|---|
| 시작 시각 | 실제 작업을 시작한 시각 |
| 종료 시각 | 실제 작업을 끝낸 시각 |
| 실제 시간 | 시작·종료 시각에서 계산한 소요 시간 |
| 실제로 한 내용 | 공부한 주제나 수행한 작업 |
| 막힌 이유 | 어려움이나 지연 원인, 없으면 생략 가능 |

실행 기록을 저장해도 원래 계획이나 할 일의 예상 시간은 바뀌지 않습니다.

시간 입력은 **24시간제**를 사용합니다.

- 낮 12시: `12시`
- 밤 12시, 자정: `00시`
- 밤 9시: `21시`

실행 기록은 수정하거나 삭제할 수 있습니다. 수정하면 소요 시간이 다시 계산되고, 삭제하면 해당 기록의 시간이 돌아보기 집계에서도 제외됩니다.

입력 오류를 줄이기 위해 다음 조건을 확인합니다.

- 종료 시각이 시작 시각보다 뒤에 있어야 합니다.
- 미래의 종료 시각은 저장할 수 없습니다.
- 한 번의 실행 기록은 24시간을 초과할 수 없습니다.
- 실제로 한 내용을 입력해야 합니다.

### See — 돌아보기

선택한 계획의 할 일을 기간별로 집계합니다.

**집계 대상은 선택한 계획에 속하고, 삭제되지 않았으며, 마감일이 선택 기간 안에 있는 할 일입니다.** 실제 시간은 이 대상 할 일에 연결된 실행 기록을 모두 합산합니다.

| 집계 항목 | 계산 기준 |
|---|---|
| 할 일 수 | 대상 할 일의 개수 |
| 완료 수 | 대상 중 현재 완료 상태인 할 일의 개수 |
| 지연 수 | 미완료이며 마감일이 서울 기준 오늘보다 앞선 할 일의 개수 |
| 막힘 수 | 막힌 이유가 하나 이상 기록된 할 일의 개수 |
| 예상 시간 | 대상 할 일의 예상 시간 합계 |
| 실제 시간 | 대상 할 일에 연결된 실행 기록의 시간 합계 |
| 시간 차이 | 실제 시간 − 예상 시간 |

완료한 할 일은 지연으로 다시 세지 않습니다. 하나의 할 일에 막힌 이유가 여러 번 기록되어도 막힘 수는 한 번만 증가합니다. 대상 자료가 없으면 시간 합계는 0입니다.

**계획 자체의 예상 시간과 할 일별 예상 시간 합계는 별도 값**입니다. 돌아보기에서는 할 일별 예상 시간을 합산합니다.

숫자를 누르면 아래의 **‘숫자의 근거’**에서 관련 할 일이나 실행 기록을 확인할 수 있습니다.

### 다음 계획으로 연결

돌아보기에서 다음에 바꿀 행동을 한 줄로 정하고, 다음 계획의 제목과 기간을 입력할 수 있습니다.

저장하면 개선점이 담긴 다음 계획이 생성되고, 원래 계획의 돌아보기와 연결됩니다. 연결된 다음 계획을 열면 가져온 개선점을 확인할 수 있습니다.

## 4. 서버 데이터베이스 저장

계획과 기록의 원본은 브라우저 저장소가 아니라 **서버의 Cloudflare D1 데이터베이스**에 저장합니다.

브라우저는 API를 통해 자료를 불러오고 저장합니다. 새로고침하면 서버에 저장된 자료를 다시 읽어 같은 ID와 값을 복원합니다.

| 테이블 | 역할 |
|---|---|
| `plans` | 현재 계획 |
| `tasks` | 계획에 연결된 할 일 |
| `runs` | 할 일에 연결된 실제 실행 기록 |
| `revisions` | 계획 수정 전 내용 |
| `completions` | 현재 완료 기록 |
| `reviews` | 돌아보기와 다음 계획 연결 |

최종 구조와 날짜·단위·집계 규칙은 다음 파일에 정리했습니다.

`contracts/pds-schema-v2.json`

### 날짜와 단위

- 계획 기간과 마감일: `YYYY-MM-DD`
- 실행 시각 저장: UTC 기준 ISO 8601
- 시간 입력과 표시: `Asia/Seoul`
- 지연 판단: 서울 기준 오늘 날짜
- 예상·실제 시간: 분
- 실제 소요 시간: 시작·종료 차이를 분으로 계산하고 반올림

## 5. 중복 방지와 삭제 처리

완료 버튼의 화면 상태만으로 중복을 막지 않고, 데이터베이스에서도 중복을 제한합니다.

- 완료 기록은 할 일 ID를 기본키로 사용합니다.
- 같은 할 일에 완료 요청이 반복되어도 현재 완료 기록은 한 건만 남습니다.
- 실행 기록은 요청 키에 고유 제약을 두어 같은 요청이 중복 저장되지 않도록 합니다.
- 완료를 되돌리면 현재 완료 기록을 제거하고 할 일을 진행 중으로 변경합니다.

할 일 삭제는 삭제 표시를 남기는 방식입니다. 삭제한 할 일은 목록과 돌아보기 집계에서 제외하지만 전체 내보내기에는 보관됩니다.

실행 기록 삭제는 해당 기록을 제거하는 방식이며, 할 일 자체와 완료 상태는 유지합니다.

## 6. 전체 자료 내보내기

오른쪽 위 **‘전체 내보내기’**를 누르면 자료를 `pds-diary.json` 파일 하나로 다운로드할 수 있습니다.

내보내는 내용은 다음과 같습니다.

- 계획
- 할 일
- 실행 기록
- 계획 수정 이력
- 완료 기록
- 돌아보기와 다음 계획 연결
- 내보낸 시각
- 시간대와 단위 정보

이 파일은 입력한 자료를 보관하기 위한 파일입니다. 앱을 만든 소스 코드와는 다릅니다.

## 7. 보안 처리

- 첫 화면에 로그인 없는 공개 상태를 안내합니다.
- 사용자 입력은 React의 텍스트 렌더링으로 표시합니다.
- 스크립트 모양의 문자열을 HTML로 직접 실행하지 않습니다.
- SQL 쿼리는 입력값을 바인딩하는 방식으로 처리합니다.
- 데이터베이스 접근은 서버에서 수행합니다.
- 저장 실패 시 오류 안내를 표시하고 입력한 폼 내용을 유지합니다.
- 소스와 Git 기록에서 비밀키 패턴을 점검했습니다.

현재는 공개 사용을 전제로 한 과제 6 버전입니다. 사용자별 접근 제한은 이 버전의 구현 범위에 포함하지 않았습니다.

## 8. 사용 방법

### 실제 활동 기록하기

1. **Plan · 할 일**에서 활동 옆 ‘기록’을 누릅니다.
2. 실제 시작·종료 시각과 작업 내용을 입력합니다.
3. ‘서버에 저장’을 누릅니다.

저장한 내용은 **Do · 실행 기록**에서 확인하고 수정·삭제할 수 있습니다.

### 계획과 실제 비교하기

1. **See · 돌아보기**를 엽니다.
2. 집계 기간과 예상·실제 시간을 확인합니다.
3. 숫자를 눌러 계산의 근거가 된 기록을 확인합니다.

### 다음 계획 만들기

1. 돌아보기 아래 ‘다음 계획 만들기’를 누릅니다.
2. 개선점 한 줄과 다음 계획의 제목·기간을 입력합니다.
3. 저장한 뒤 ‘연결된 다음 계획 열기’로 이동합니다.

## 9. 검증 내용

### 자동 검증

`t06/checks.mjs`는 공개 데이터와 분리된 테스트용 SQLite에서 다음 내용을 확인합니다.

- 계획 수정 전 내용 보존
- 계획 ID 유지
- 완료 요청 중복 방지
- 완료 수의 중복 증가 방지
- 실행 요청 중복 방지
- 실행 시간 계산
- 실행 기록 수정과 삭제
- 미래 시각 입력 거절
- 원래 예상 시간 보존
- 재조회 시 ID와 값 유지
- 완료 되돌리기
- 할 일 삭제
- 개선점과 다음 계획 연결
- 집계 계산과 삭제 항목 제외
- 막힘 중복 집계 방지
- 완료 항목의 지연 중복 집계 방지
- 빈 자료의 시간 합계 0
- 스크립트 문자열의 문자 렌더링

의존성이 설치된 환경에서 다음 명령어로 실행합니다.

```bash
node t06/checks.mjs
```

### 직접 확인한 내용

- 실제 계획과 할 일 5개 입력
- 실제 실행 기록 5건 입력
- 계획 수정 이력 확인
- 예상 시간과 실제 시간 집계 확인
- 집계 숫자에서 근거 기록 확인
- 다음 계획으로 개선점 전달
- 새로고침 후 자료 유지
- 전체 JSON 내보내기
- 완료와 되돌리기
- 빠르게 반복 클릭했을 때 완료 수 중복 증가 없음
- 검색·필터·정렬
- 할 일 추가와 삭제
- 스크립트 문자열의 화면 표시
- 시크릿 창에서 로그인 없이 앱 접근
- 시크릿 창에서 소스 ZIP 다운로드

화면에서의 직접 확인과 자동 검증은 구분해서 진행했습니다.

앱은 현재 실행 주소에서 서버 기능과 데이터베이스를 포함해 운영됩니다. 이 저장소에 소스를 업로드하는 것만으로 별도의 실행 서버나 데이터베이스가 생성되지는 않습니다.

다른 환경에서 실행하려면 의존성 설치뿐 아니라 D1 바인딩과 데이터베이스 마이그레이션 설정이 필요합니다.

## 12. 짧은 확인 방법

1. **어디로 가나요:** 실행 주소에서 ‘보안 솔루션 엔지니어 취업 준비’ 계획을 선택합니다.
2. **무엇을 하나요:** ‘See · 돌아보기’를 열고 ‘실제 시간’ 숫자를 누릅니다.
3. **통과 모습:** 입력 자료에 맞는 실제 시간 합계와 근거 실행 기록이 표시됩니다.
4. **안 될 때 모습:** 자료 조회·저장 실패 시 오류 안내가 표시되고, 저장 폼의 입력은 유지됩니다.

## 13. AI와 직접 한 일

### AI에게 맡긴 일

앱 화면, 서버 데이터베이스 저장, 계획 이력, 집계와 중복 방지 기능 구현 및 자동 검증을 맡겼습니다. 사용 중 발견한 글씨 색상과 시간 입력 문제도 수정하도록 요청했습니다.

### 직접 판단하고 수행한 일

취업 준비 활동 5개와 계획 기간을 정했습니다. 활동별 예상 시간과 실제 작업 기록을 직접 입력하고, 새로고침·내보내기·완료·검색·필터·정렬·공개 접근 등을 확인했습니다.

### 직접 선택한 내용

돌아보기에서 다음 계획으로 가져갈 문구를 직접 정했습니다. 입력 자료와 공개할 내용은 본인의 실제 활동을 기준으로 선택했습니다.

## 14. 진행하며 배운 점

- 계획한 시간과 실제로 사용한 시간은 따로 기록해야 비교할 수 있습니다.
- 실행 기록에는 전체 계획 기간이 아니라 한 번의 실제 작업 시간을 넣어야 합니다.
- 오전 12시와 오후 12시는 혼동하기 쉬워 24시간제 입력이 도움이 됐습니다.
- 데이터가 화면에 보이는 것과 서버에 저장되는 것은 구분해서 확인해야 합니다.
- 집계 숫자만 표시하는 것보다 그 숫자의 근거 기록을 확인할 수 있어야 내용을 이해하기 쉽습니다.
- 실제 사용하면서 글씨 색상, 시간 입력, 기록 수정 같은 불편을 발견하고 개선할 수 있었습니다.
