# 플랜두씨 다이어리 · 과제 6

본인의 보안 솔루션 엔지니어 취업 준비 계획(2026-10-09~2026-12-31)을 바탕으로 만든 Plan → Do → See 다이어리입니다. 로그인 없이 공개되어 있으며 링크를 아는 누구나 자료를 읽고 수정할 수 있습니다. 민감한 정보를 넣지 마세요.

## 기능
- 계획 기간, 우선순위, 성공 기준, 예상 시간과 수정 전 이력 보관
- 할 일 추가, 수정, 완료, 되돌리기, 소프트 삭제 / 검색, 상태 필터, 결정적인 정렬
- 서울 시각으로 입력한 실행 기록을 UTC로 저장하고 실제 소요 분을 계산
- DB 기본키와 고유 제약으로 완료와 실행 요청 중복 방지
- 마감일 기간별 할 일, 완료, 지연, 막힘 수 및 예상·실제·차이 집계, 클릭 가능한 근거
- 개선점을 담은 다음 계획 생성 및 연결
- 전체 6개 테이블을 JSON 하나로 내보내기

## 데이터와 보안
Cloudflare D1 SQLite가 원본 저장소입니다. React 텍스트 렌더링과 SQL 바인딩을 사용합니다. 비밀키는 필요 없으며 DB는 서버 바인딩으로 접근합니다. 구조와 날짜·집계 규칙은 `contracts/pds-schema-v2.json`에 있습니다. 스키마는 Drizzle 마이그레이션으로 적용합니다.

초기 계획 1건과 사용자가 제공한 할 일 5건만 저장합니다. 임의 실행 기록은 넣지 않습니다. 예상 시간 0분은 미설정 값이며 자격증의 60분은 평일 공부 1회의 기준입니다. 주말 목표 120~180분은 태그로 보존합니다. 실제 실행 기록 3건, 계획 수정 이력, 개선점 전달은 본인이 앱에서 채워야 합니다.

## 검증
`node t06/checks.mjs`: 격리된 SQLite에서 계획 이력, 중복 완료, 실행 중복, 원래 값 보존, 재조회, 되돌리기, 삭제, 다음 계획 연결을 검증합니다. 테스트 자료는 공개 DB에 들어가지 않습니다.

## 짧은 확인 방법
1. 결과물 주소의 첫 화면에서 계획과 할 일 목록을 확인합니다.
2. 할 일의 ‘기록’ → 시작·끝·내용 입력 → ‘서버에 저장’을 누릅니다.
3. 새로고침 후 같은 실행 기록이 남고, See에서 시간을 눌러 근거 기록이 보이면 통과입니다.
4. 불러오기·저장 실패 시 오류 안내가 표시되며, 저장 폼의 입력은 남습니다.

## AI와 내 판단 · 제출 전 본인 확인 필요
- AI에게 맡긴 일: 화면과 서버 DB 기능 구현, 구조 문서 작성, 자동 검증.
- 내가 직접 판단한 일: 취업 준비 활동 5개, 계획 기간, 정보보안산업기사 공부 시간.
- AI 제안을 따르지 않은 일: 실제로 거절한 제안이 없다면 그 이유를 본인이 작성합니다.

브라우저 UI 및 WebMCP 런타임 검증은 이 환경에서 수행하지 않았습니다. 새 시크릿 창 공개 접근, 실제 기록 3건, 스크립트 입력의 문자 표시 및 새로고침 증거를 본인이 확인해야 합니다.

## 보완 사항
실행 기록은 같은 ID로 수정할 수 있고 삭제 시 실제 시간과 막힘 집계에도 즉시 반영됩니다. 한 번의 실행은 실제 과거 시각, 0분 초과~24시간 이내여야 하며 작업 내용이 필요합니다. 이미 저장된 잘못된 기간은 자동 변경하지 않고 수정 안내를 표시합니다.

자동 검증 추가: 실행 수정·삭제, 미래 시각 거절, 집계 7항목과 근거, 삭제 항목 제외, 완료 항목 지연 제외, 막힘 중복 제외, 서울 오늘 마감 제외, 빈 합계 0, React 스크립트 문자 이스케이프. 전체 타입 검사와 최종 빌드를 수행합니다. 공개 DB 실제 기록과 화면 증거는 본인이 확인해야 합니다.
